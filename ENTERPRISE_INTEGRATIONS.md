# Место будущих интеграций с 1С:ЗУП и Documentolog

Войдите как HR → «Корпоративные системы». В «Управлении данными» также есть ссылка «1С и Documentolog». Страница доступна по /integrations, кадровые mock API — только роли hr.

## Что показать на защите

1. Схема: **1С:ЗУП → Qadam11 → Documentolog**.
2. Блок 1С:ЗУП: в будущем получаем официальный профиль, должность, отдел, дату приёма и остаток отпуска.
3. Блок Documentolog: в будущем передаём данные согласованной заявки для оформления и подписания документа, принимаем его статус.
4. Нажмите «Посмотреть пример обмена». Сервер вернёт пример запроса/ответа и пояснит результат. Статус «Заглушка · не подключено» остаётся видимым.

Фраза для защиты: «В прототипе есть отдельное место для будущих корпоративных интеграций. Мы показали направление обмена и проверяем его на локальных заглушках. Для реального внедрения нужны доступы компании, согласование полей и маршрутов документов».

## Что реализовано

- GET /api/admin/integrations: статусы двух интеграций, назначение и перечень полей. Всегда mode=mock, status=not_connected, external_calls=false.
- POST /api/admin/integrations/1c-zup/preview с пустым JSON: пример получения кадровых данных.
- POST /api/admin/integrations/documentolog/preview с пустым JSON: пример подготовки документа по отпуску.
- Для POST обязательны сессия HR и CSRF. Произвольные персональные данные, настройки и ключи через эти маршруты не принимаются.

В app/integrations.py выделены OneCZupStub и DocumentologStub. Это граница для последующей замены адаптерами настоящих сервисов. Внутренние поля примеров не являются официальной спецификацией API 1С или Documentolog; соответствие с API компании нужно согласовать отдельно.

## Границы заглушек

Данные вымышленные. Внешних вызовов нет, учётные записи внешних систем не нужны. Пример не создаёт заявку или документ в базе, не меняет профиль и баланс отпуска, не подписывает документ и не считается успешной интеграцией. В реальной организации источником профиля и остатка пока остаётся локальная SQLite. У Gemini отдельное серверное подключение; заглушки с ним не связаны.

## Оформление рабочего пространства

На широких экранах добавлена спокойная объёмная надпись JANA с помощью CSS: перспективный наклон, слои тени и небольшое плавное смещение. Декор расположен позади содержимого, не перехватывает нажатия и скрыт от screen reader. При prefers-reduced-motion движение отключается; на экранах уже 1024 px и при forced-colors декор скрыт. Дополнительных графических библиотек и внешних ресурсов нет. Браузерная визуальная проверка остаётся неподтверждённой из-за ограничения инструмента; перед показом проверьте читаемость на экране команды.
